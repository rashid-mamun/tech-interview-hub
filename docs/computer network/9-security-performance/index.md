## 70. What are common Internet security threats (e.g., phishing, DDoS attacks), and how are they mitigated?
ইন্টারনেটে কিছু সাধারণ এবং মারাত্মক সিকিউরিটি থ্রেট বা হুমকি রয়েছে:
- **Phishing (ফিশিং):** সোশ্যাল ইঞ্জিনিয়ারিং ব্যবহার করে ইউজারকে বোকা বানিয়ে (যেমন ব্যাঙ্কের ফেক ইমেইল পাঠিয়ে) তার আইডি-পাসওয়ার্ড হাতিয়ে নেওয়া। *প্রতিকার:* 2FA (Two-Factor Authentication) এবং ইমেইল ফিল্টারিং ব্যবহার।
- **Malware & Ransomware:** ক্ষতিকর সফটওয়্যার যা সিস্টেমে ঢুকে ডেটা চুরি করে বা ফাইল লক করে টাকা দাবি করে। *প্রতিকার:* আপডেটেড অ্যান্টিভাইরাস এবং নিয়মিত ডেটা ব্যাকআপ রাখা।
- **DDoS (Distributed Denial of Service):** হাজার হাজার ফেক রিকোয়েস্ট পাঠিয়ে সার্ভারকে ডাউন করে দেওয়া। *প্রতিকার:* Cloudflare এর মতো WAF বা অ্যান্টি-ডিডস সার্ভিস ব্যবহার করা।

### What is the difference between a volumetric DDoS and an application-layer DDoS?
- **Volumetric DDoS:** এখানে হ্যাকাররা টার্গেট সার্ভারের নেটওয়ার্ক ব্যান্ডউইথ (Network Bandwidth) টার্গেট করে। তারা বিশাল ভলিউমের ডেটা (যেমন সেকেন্ডে ১০০ গিগাবাইট) পাঠিয়ে ইন্টারনেট লাইন জ্যাম করে দেয়, যাতে লিজিটিমেট রিকোয়েস্ট ঢুকতে না পারে।
- **Application-layer DDoS (Layer 7):** এখানে ব্যান্ডউইথ টার্গেট করা হয় না। হ্যাকাররা এমন কিছু জটিল HTTP রিকোয়েস্ট (যেমন ভারী পেজ সার্চ বা লগইন) পাঠায় যা প্রসেস করতে সার্ভারের CPU বা RAM ফুল হয়ে সার্ভার ক্র্যাশ করে। এটি প্রতিহত করা কঠিন।

### What is a man-in-the-middle (MitM) attack and how is it prevented?
**MitM Attack:** ক্লায়েন্ট এবং সার্ভারের ঠিক মাঝখানে হ্যাকার একটি গুপ্তচর হিসেবে বসে থাকে। উদাহরণ হিসেবে ফ্রি পাবলিক ওয়াইফাইয়ের কথা বলা যায়, যেখানে হ্যাকারের রাউটারের ভেতর দিয়ে ইউজাররা ফেক ওয়েবসাইটে লগইন করে আর হ্যাকার সব ডেটা স্নাইফ করে (Sniffing)।
**প্রতিকার (Prevention):** সব ধরনের কমিউনিকেশনে **HTTPS (TLS/SSL)** ব্যবহার করা। এটি ডেটাকে এনক্রিপ্ট করে ফেলে, ফলে হ্যাকার ডেটা ক্যাপচার করলেও তা দেখতে বা পড়তে পারে না।

## 71. How do Virtual Private Networks (VPNs) protect Internet users?
**VPN (Virtual Private Network)** ইউজারের ডিভাইস থেকে ইন্টারনেটের গন্তব্য পর্যন্ত একটি ভার্চুয়াল, সুরক্ষিত এবং এনক্রিপ্টেড "টানেল" (Tunnel) তৈরি করে।
- **IP Masking:** ইউজারের আসল IP অ্যাড্রেস হাইড করে VPN সার্ভারের IP দেখায়, ফলে ওয়েবসাইট বা হ্যাকাররা ইউজারের আসল লোকশন ট্রেস করতে পারে না।
- **Encryption:** ইউজার কী সার্চ করছে বা কী ডেটা পাঠাচ্ছে, তা ইউজারের লোকাল ISP বা ওয়াইফাই মালিক ফিল্টার বা পড়তে পারে না।

### What is the difference between a site-to-site VPN and a remote-access VPN?
- **Site-to-Site VPN:** সাধারণত কোম্পানিগুলো এটি ব্যবহার করে। ধরুন, ঢাকায় একটি অফিস এবং চট্টগ্রামে আরেকটি অফিস আছে। দুটি অফিসের রাউটারের মাঝে এই VPN তৈরি করা হয়, ফলে ঢাকা অফিসের কর্মীরা সরাসরি চট্টগ্রাম অফিসের লোকাল সার্ভারগুলো এক্সেস করতে পারে (যেন তারা একই বিল্ডিংয়ে আছে)।
- **Remote-Access VPN:** এটি একজন স্বতন্ত্র ইউজারের জন্য। আপনি যখন বাসা থেকে ল্যাপটপে VPN ক্লায়েন্ট ওপেন করে ইন্টারনেটে যান বা অফিসে কানেক্ট করেন, তখন এটি রিমোট অ্যাক্সেস ভিপিএন।

### What protocols do VPNs use (OpenVPN, WireGuard, IPSec)?
1. **IPSec (Internet Protocol Security):** এটি বেশ পুরোনো কিন্তু খুবই সিকিউর একটি প্রোটোকল। এটি Network Layer (Layer 3) এ কাজ করে এবং সাধারণত Site-to-Site VPN এর কমার্শিয়াল রাউটারগুলোতে বেশি ব্যবহৃত হয়।
2. **OpenVPN:** এটি সবচেয়ে জনপ্রিয় ওপেন-সোর্স প্রোটোকল। এটি অনেক বেশি সিকিউর এবং কাস্টমাইজ করা যায়। এটি TCP বা UDP যেকোনো পোর্টে চলতে সক্ষম, ফলে ফায়ারওয়াল ব্লক করা কঠিন।
3. **WireGuard:** এটি সর্বাধুনিক এবং সবচেয়ে ফাস্ট প্রোটোকল। এর কোডবেস (Codebase) ওপেনভিপিএন এর তুলনায় অনেক ছোট (মাত্র 4000 লাইন), যার কারণে এটি মোবাইলের ব্যাটারি কম টানে এবং কানেকশন স্পিড অবিশ্বাস্য রকমের ফাস্ট।



## 72. What is bandwidth, and how does it affect Internet performance?
**Bandwidth (ব্যান্ডউইথ)** হলো একটি ইন্টারনেট কানেকশন বা ক্যাবলের মধ্য দিয়ে নির্দিষ্ট সময়ে (সাধারণত প্রতি সেকেন্ডে) সর্বোচ্চ কতটুকু ডেটা আদান-প্রদান করা সম্ভব, তার ক্ষমতা (Capacity)। 
- একে আমরা পানির পাইপের সাথে তুলনা করতে পারি। পাইপ যত বেশি মোটা (ব্যান্ডউইথ) হবে, তত বেশি পানি (ডেটা) একবারে যেতে পারবে।
- ইন্টারনেট ব্রাউজিং, বড় ফাইল ডাউনলোড, এবং 4K ভিডিও স্ট্রিমিংয়ে বেশি ব্যান্ডউইথের প্রয়োজন হয়।

### What is the difference between bandwidth and latency?
| বৈশিষ্ট্য | Bandwidth (ব্যান্ডউইথ) | Latency (ল্যাটেন্সি) |
|---|---|---|
| **সংজ্ঞা** | একই সময়ে একসাথে কতটুকু ডেটা ট্রান্সফার হতে পারবে, তার ধারণক্ষমতা। | ডেটা প্যাকেটের এক প্রান্ত থেকে অন্য প্রান্তে পৌঁছাতে এবং ফিরে আসতে (RTT) কতটুকু সময় লাগে। |
| **পরিমাপ** | Mbps বা Gbps (মেগাবিট/গিগাবিট প্রতি সেকেন্ড)। | Milliseconds বা ms (মিলি-সেকেন্ড)। |
| **উপমা** | রাস্তার প্রস্থ (রাস্তা যত চওড়া, তত গাড়ি একসাথে যেতে পারবে)। | গাড়ির গতি এবং রাস্তার দূরত্ব (গাড়িটা এক শহর থেকে অন্য শহরে যেতে কত সময় নেবে)। |

### What is jitter and how does it affect real-time applications?
**Jitter (জিটার)** হলো ল্যাটেন্সির স্থায়িত্বের তারতম্য বা পরিবর্তনশীল ল্যাটেন্সি।
- ধরুন, আপনার পিসির নরমাল পিং (Ping) বা ল্যাটেন্সি হলো 20ms। কিন্তু হঠাৎ তা বেড়ে 80ms, আবার 30ms, আবার 150ms হচ্ছে। ল্যাটেন্সির এই উঠানামাকেই জিটার বলা হয়।
- **প্রভাব:** জিটারের কারণে ভিডিও কলিং বা অনলাইন গেমিং মারাত্মকভাবে প্রভাবিত হয়। ভয়েস কলের সময় কথা থেমে যাওয়া, পরপর দ্রুত কথা আসা, বা ভিডিও ফ্রেমে ড্রপ দেখা দিলে বুঝতে হবে নেটওয়ার্কে জিটার সমস্যা আছে।

## 73. What is Internet speed tests, and what factors influence the results?
ইন্টারনেট স্পিড টেস্ট (যেমন Ookla Speedtest বা Fast.com) হলো এমন কতগুলো টুল যা আপনার ডিভাইস থেকে তাদের সবচেয়ে কাছের একটি ডেডিকেটেড লোকাল সার্ভারের সাথে সবচেয়ে বড় ফাইল ডাউনলোড/আপলোড করে আপনার ইন্টারনেট কানেকশনের সর্বোচ্চ ব্যান্ডউইথ মাপে।
- **ফ্যাক্টরস:** স্পিড টেস্টের রেজাল্ট নির্ভর করে আপনার রাউটারের ক্ষমতা, ওয়াইফাইয়ের সিগন্যাল স্ট্রেন্থ (2.4GHz নাকি 5GHz), এবং লোকাল আইএসপির (ISP) ব্যাকবোন স্পিডের ওপর।

### Why might a speed test show good results but an application still feel slow?
মাঝে মাঝে আমরা স্পিড টেস্টে 50 Mbps দেখি, কিন্তু ফেসবুক বা কোনো ওয়েবসাইট লোড হতে অনেক সময় নেয়। এর কারণ:
1. **সার্ভার লোকেশন:** স্পিড টেস্ট আপনার আইএসপি-এর খুব কাছের (Local ISP) একটি সার্ভারের সাথে চেক করে। কিন্তু আপনি যে ওয়েবসাইটটি ব্রাউজ করছেন, তার সার্ভার হয়তো আমেরিকায় অবস্থিত, যার ফলে প্রচুর ল্যাটেন্সি হয়।
2. **ডোমেইন রেজল্যুশন (DNS):** আপনার ব্যান্ডউইথ ভালো, কিন্তু আপনি আইএসপি-এর যে লোকাল DNS সার্ভার ব্যবহার করছেন, সেটি খুব স্লো। ফলে সে আইপি খুঁজে পেতেই ৫ সেকেন্ড কনজিউম করে ফেলে।
3. **সার্ভার লোড:** যার ওয়েবসাইট আপনি ব্রাউজ করছেন, তার সার্ভারই হয়তো খারাপ বা লোড নিতে পারছে না।

### What is bufferbloat and how does it affect perceived performance?
**Bufferbloat** হলো রাউটারের ভেতরে সৃষ্ট একটি আর্টিফিশিয়াল ট্রাফিক জ্যাম বা কনজেশন।
- আধুনিক রাউটারগুলোতে ট্রাফিক ম্যানেজ করার জন্য অনেক বড় মেমোরি বা বাফার (Buffer) দেওয়া থাকে।
- যখন নেটওয়ার্কে অনেক ডেটা (যেমন কেউ টরেন্টে বড় ফাইল ডাউনলোড দিচ্ছে) একসাথে আসে, তখন রাউটার ডেটাগুলো ড্রপ না করে বিশাল বাফারে লোড করে রাখে। 
- কিন্তু ওই বিশাল ব্যাগের ভেতর যখন আপনার ভিডিও কলিং এর ছোট ডেটাগুলো ঢোকে, তখন তাদের কিউ (Queue) বা সিরিয়ালের জন্য অনেকক্ষণ অপেক্ষা করতে হয়। ফলে আপনার ইন্টারনেট স্পিড পুরো থাকার পরও গেমের পিং বেড়ে যায় বা কল ল্যাগ করে। 
- ভালো 라উটারগুলো SQM (Smart Queue Management) ব্যবহার করে বাফারব্লোট সমাধান করে।



## 74. How do backend developers secure APIs against common attacks like SQL injection or XSS? 
এপিআই সিকিউর রাখার জন্য ব্যাকএন্ড ডেভেলপারদের ডেটা স্যানিটাইজেশন এবং অ্যাপ্লিকেশন সিকিউরিটি রুলগুলো কড়াকড়িভাবে মেনে চলতে হয়। 
- তারা ইনপুট ভ্যালিডেশন করেন যেন ইউজার অপ্রত্যাশিত কোনো ডেটা ফর্মে পাঠাতে না পারে।
- পাসওয়ার্ড সেভ করার জন্য Bcrypt/Argon2 এর মত হ্যাশিং অ্যালগরিদম ব্যবহার করেন।
- অথেনটিকেশন এর জন্য OAuth বা JWT টোকেন ব্যবহার করেন এবং HTTPOnly কুকির মাধ্যমে টোকেন হাইড করে রাখেন।

### What is parameterized querying and how does it prevent SQL injection?
**SQL Injection** হলো হ্যাকার কর্তৃক ইউজারের ইনপুট ফিল্ডে (যেমন লগইন বক্সে) ম্যালিসিয়াস এসকিউএল কোড দিয়ে ডাটাবেস হ্যাক করা। 
- **প্যারামিটারাইজড কোয়েরি (Parameterized Query):** ডেভেলপাররা যখন ডেটাবেসে কোয়েরি পাঠান, তখন ইউজারের ইনপুট করা ডেটাকে সরাসরি SQL স্ট্রিং এর সাথে কনক্যাট (Concat) বা যোগ করেন না। তার বদলে તેઓ কোয়েরিতে শুধু প্লেসহোল্ডার (যথা `?` বা `$1`) দিয়ে রাখেন। 
- **প্রতিরোধ:** ডাটাবেস লেভেলের ড্রাইভার ইউজারের দেওয়া ইনপুটকে কোড হিসেবে না পড়ে, শুধু ডাটা বা ভ্যালিউ হিসেবে পার্স করে। ফলে ইউজারের বক্সে লেখা SQL কমান্ডগুলো ডাটাবেসে গিয়ে রান হতে পারে না, তা শুধুমাত্র একটি টেক্সট হিসেবে গণ্য হয়।

### What is the difference between stored XSS and reflected XSS?
**Cross-Site Scripting (XSS)** হলো এমন একটি আক্রমণ যেখানে হ্যাকার ওয়েবসাইটের ফ্রন্টএন্ডে ক্ষতিকর জাভাস্ক্রিপ্ট ইনজেক্ট করে।
- **Stored XSS:** হ্যাকার তার ম্যালিসিয়াস জাভাস্ক্রিপ্ট কোডটি সরাসরি ওয়েবসাইটের ডেটাবেসে (যেমন একটি ব্লগের কমেন্ট বা রিভিউ বক্সে) সেভ করতে সক্ষম হয়। এরপর যতজন ইউজার ওই পেজ বা পোস্টটি দেখবে, সবার ব্রাউজারে ওই ক্ষতিকর কোডটি অটোমেটিক রান হবে (এটি সবচেয়ে ডেঞ্জারাস)।
- **Reflected XSS:** এটি ডেটাবেসে সেভ হয় না। হ্যাকার একটি ফেক বা ক্ষতিকর URL তৈরি করে (যাতে জাভাস্ক্রিপ্ট কোড প্যারামিটার হিসেবে যুক্ত থাকে) এবং ইউজারকে সেটি ইমেইলে দিয়ে ক্লিক করতে বাধ্য করে। লিংকে ক্লিক আসামাত্রই ডাটাগুলো ব্রাউজারে রিফ্লেক্ট করে স্ক্রিপ্টটি রান করায়।

### How do Content Security Policy (CSP) headers help mitigate XSS?
**CSP (Content Security Policy)** হলো সার্ভার থেকে ব্রাউজারকে পাঠানো একটি পাওয়ারফুল HTTP রেসপন্স হেডার। 
- এর কাজ হলো ইন-লাইন (In-line) জাভাস্ক্রিপ্ট রান করা বন্ধ করা এবং ব্রাউজারকে বলে দেওয়া যে ওয়েবসাইটটি শুধু কোন ডোমেইন বা সোর্স থেকে জাভাস্ক্রিপ্ট, সিএসএস, এবং ইমেজ লোড বা রান করতে পারবে।
- যদি কোনো হ্যাকার XSS এর মাধ্যমে কোনো ক্ষতিকর কোড ওয়েবসাইটে ঢুকিয়েও দেয়, ব্রাউজার ওই স্ক্রিপ্ট দেখে CSP রুলস চেক করবে। যেহেতু স্ক্রিপ্টের সোর্সটি অনুমোদিত ডোমেইনের (Trusted Domain) লিস্টে নেই, তাই ব্রাউজার সাথে সাথেই সেই স্ক্রিপ্ট এক্সিকিউট করা ব্লক করে দেবে।

## 75. What is the role of API gateways in managing and securing backend services? 
**API Gateway (এপিআই গেটওয়ে)** হলো মাইক্রোসার্ভিস মেকানিজমে কাজ করা ব্যাকএন্ড সিস্টেমগুলোর প্রবেশদ্বার বা ফ্রন্ট-ডোর।
- ক্লায়েন্ট (যেমন মোবাইল অ্যাপ, ওয়েব ব্রাউজার) সরাসরি পেছনের মূল সার্ভিসগুলোর (যেমন ইউজার সার্ভিস, পেমেন্ট সার্ভিস) সাথে যোগাযোগ না করে শুধুমাত্র API Gateway-কে রিকোয়েস্ট পাঠায়।
- গেটওয়ে সেই রিকোয়েস্ট রিসিভ করে, চেক বা রাউটিং করে সঠিক মাইক্রোসার্ভিসের কাছে পাঠিয়ে দেয়। এটি মূল ব্যাকএন্ডকে আড়াল করে এক্সট্রা সিকিউরিটি এবং ট্রাফিক ম্যানেজমেন্ট প্রদান করে।

### What features does an API gateway typically provide?
- **Authentication & Authorization:** প্রতিটি রিকোয়েস্টের JWT টোকেন বা API Key চেক করা।
- **Rate Limiting:** স্প্যামারদের ব্লক করে সার্ভারের ট্রাফিক লিমিট করা।
- **Request Routing / Composition:** একটি রিকোয়েস্ট পেয়ে কয়েকটি মাইক্রোসার্ভিস থেকে ডাটা একসাথে এনে ক্লায়েন্টকে পাঠানো (BFF Pattern)।
- **Caching & Logging:** ঘন ঘন রিকোয়েস্ট আসা ডাটাগুলো ক্যাশ করা এবং সার্ভারের সব লগ এক জায়গায় মনিটর করা।

### What is the difference between an API gateway and a reverse proxy?
এই দুটি জিনিসের খুব কাছাকাছি কাজ হলেও ফিলোসফিতে কিছুটা পার্থক্য আছে:
- **Reverse Proxy (যেমন Nginx, HAProxy):** এটি মূলত নেটওয়ার্ক বা সার্ভার লেভেলে কাজ করে। এর প্রধান কাজ হলো লোড ব্যালেন্সিং, ক্যাশিং এবং ক্লায়েন্টের রিকোয়েস্টকে পেছনের সার্ভারে ফরওয়ার্ড করা। এটি সাধারণত API এর কনটেন্ট বা লজিক পড়ে না।
- **API Gateway:** এটি রিভার্স প্রক্সির উপরে থাকা একটি সফটওয়্যার লেয়ার। এটি শুধু ফরোয়ার্ড করেই ক্ষান্ত হয় না, এটি API লেভেলের কাজ করে—যেমন অথেনটিকেশন চেক করা, রেট লিমিটিং দেওয়া, ডেটা ট্রান্সফরমেশন (XML থেকে JSON), এবং বিলিং/অ্যানালিটিক্স ম্যানেজমেন্ট।

### How do Kong, AWS API Gateway, and Nginx compare as API gateways?
| প্ল্যাটফর্ম | ধরন | বৈশিষ্ট্য |
|---|---|---|
| **Kong** | Open-source API Gateway | Nginx এর ওপরে তৈরি করা একটি ডেডিকেটেড এপিআই গেটওয়ে অ্যাপ্লিকেশন। এর প্লাগইন (Plugins) ইকোসিস্টেম অনেক উন্নত (Auth, Rate Limiting)। মাইক্রোসার্ভিস এবং কন্টেইনার (Kubernetes) বেসড আর্কিটেকচারে খুব জনপ্রিয়। |
| **AWS API Gateway** | Fully Managed Cloud Service | আমাজনের একটি সার্ভারলেস (Serverless) সার্ভিস। সার্ভার মেইনটেন করার কোনো ঝামেলা নেই। অটো-স্কেল হয় এবং AWS Lambda বা DynamoDB এর সাথে ডিরেক্ট নেটিভভাবে খুব ভালোভাবে কাজ করে। |
| **Nginx** | Web Server / Reverse Proxy | এটি ট্র্যাডিশনাল এবং সবচেয়ে ফাস্ট রিভার্স প্রক্সি। চাইলে কনফিগ ফাইল লিখে একে বেসিক এপিআই গেটওয়ে বানানো যায়, কিন্তু Kong বা AWS এর মতো রেডিমেড API ম্যানেজমেন্ট প্লাগইন এতে থাকে না (Nginx Plus ছাড়া)। |
